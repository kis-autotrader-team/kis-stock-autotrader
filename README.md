# 국내·미국주식 자동매매 프로그램

한국투자증권 Open API로 국내·미국주식 시세를 함께 수집하고, 여러 기술적 지표를 조합해 미리 정한 위험 한도 안에서 주문하는 Windows PC 프로그램입니다.

- 목적: 포트폴리오·과제 (품질은 상용 수준 목표)
- 팀: 2명 / 기간: 2주
- 설계 내용: [설계_정리.md](설계_정리.md)
- 개발 환경: [docs/개발환경.md](docs/개발환경.md)
- 역할 분담: [docs/역할분담.md](docs/역할분담.md)

> 처음 받았다면 **개발환경.md → 이 README의 규칙 → 역할분담.md** 순서로 읽어 주세요.

## 필수 규칙 요약 (예외 없음)

1. **커밋은 작업 단위마다 남긴다.** 형식: `종류: 요약` → [2장](#2-커밋-규칙-커밋은-무조건-남긴다)
2. **모든 변경은 PR로 올리고 상대 승인 후 머지한다.** main 직접 push는 GitHub 설정으로 막혀 있음 → [3장](#3-pr-규칙-pr도-무조건-남긴다)
3. **주석을 확실하게 단다.** 모든 모듈·클래스·공개 함수에 docstring, 돈 관련 코드는 줄 단위 주석 → [4장](#4-주석-규칙-확실하게)
4. **명세서를 코드와 같이 만든다.** 모듈을 새로 만들거나 인터페이스를 바꾸면 같은 PR에 `docs/명세서/<모듈명>.md`를 만들거나 고친다. 주석이나 명세서가 빠진 PR은 리뷰에서 반려한다 → [5장](#5-명세서-규칙-코드와-같이)
5. **작업보고를 md로 남겨 서로 본다.** AI 초안은 가공해서 직접 쓴다 → [6장](#6-작업-보고-규칙-서로에게-md로-보고)
6. **비밀값은 절대 커밋하지 않는다.** → [7장](#7-비밀값-규칙)

## 팀 규칙 (반드시 지킬 것)

### 1. Git 사용 규칙

**브랜치**
- `main`: 항상 실행 가능한 상태만 유지합니다. **직접 push 금지.**
- 작업 브랜치 이름: `종류/이름-작업내용`
  - 예: `feat/a-kis-auth`, `fix/b-dashboard-rate`, `docs/a-risk-spec`
- 작업 하나당 브랜치 하나. 작업이 끝나면 PR로만 `main`에 합칩니다.

**작업 순서**
```bash
git switch main
git pull                          # 시작 전에 항상 최신화
git switch -c feat/a-kis-auth     # 작업 브랜치 생성
# ... 작업 ...
git add <파일>
git commit                        # 아래 커밋 규칙대로 작성
git push -u origin feat/a-kis-auth
gh pr create                      # PR 템플릿이 자동으로 뜸
```

### 2. 커밋 규칙 (커밋은 무조건 남긴다)

- **작업 단위마다 커밋합니다.** 하루치 작업을 커밋 하나로 몰지 않습니다.
- 커밋 메시지 형식:
  ```
  종류: 한 줄 요약 (50자 이내)

  - 무엇을 바꿨는지
  - 왜 바꿨는지
  - 관련 명세서/작업보고 파일 (있으면)
  ```
- 종류

| 종류 | 언제 |
|---|---|
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `refactor` | 동작은 같고 구조만 변경 |
| `test` | 테스트 추가·수정 |
| `docs` | 문서, 명세서, 작업보고 |
| `chore` | 설정, 의존성, 빌드 |

- 예시
  ```
  feat: 해외주식 현재가 조회 추가

  - KIS 해외주식 현재가 REST API 연동
  - 국내/해외 응답을 공통 Quote 모델로 변환
  - 명세서: docs/명세서/api.md
  ```
- 금지: `수정`, `ㅇㅇ`, `final`, `asdf` 같은 의미 없는 메시지

### 3. PR 규칙 (PR도 무조건 남긴다)

- 모든 변경은 PR로만 `main`에 합칩니다. 혼자 다 했어도 PR을 만듭니다.
- PR 본문은 템플릿(`.github/pull_request_template.md`)을 채웁니다.
- **리뷰어는 상대방입니다.** 상대가 승인해야 머지합니다.
- 머지 방식: **Create a merge commit** (Squash 금지). 커밋 기록이 그대로 남아야 합니다.
- 머지한 브랜치는 삭제해도 되지만 PR은 닫지 말고 머지 상태로 남깁니다.
- PR 하나는 리뷰 가능한 크기로 유지합니다 (대략 변경 400줄 이내 권장).

### 4. 주석 규칙 (확실하게)

- **모든 모듈, 클래스, 공개 함수에 docstring을 씁니다.** 형식은 Google 스타일, 한국어.
  ```python
  def check_daily_loss(current_pnl: Decimal, limit_pct: Decimal) -> bool:
      """일일 손실 한도를 넘었는지 확인한다.

      Args:
          current_pnl: 오늘 실현+평가 손익률(%). 손실이면 음수.
          limit_pct: 일일 최대 손실 한도(%). 예: -2.0

      Returns:
          한도를 넘었으면 True (신규 주문을 막아야 함).

      Raises:
          ValueError: limit_pct가 0 이상일 때.
      """
  ```
- 코드 안 주석은 **"무엇"보다 "왜"** 를 씁니다.
  - 나쁜 예: `# 1초 쉰다`
  - 좋은 예: `# KIS 모의투자 호출 제한을 넘지 않기 위해 1초 대기`
- 숫자를 그냥 쓰지 말고 상수로 빼고 의미를 주석으로 남깁니다.
- **돈과 관련된 코드(주문, 위험 한도, 수량 계산)는 줄 단위로 주석을 답니다.**
- API 응답 필드명(예: `ovrs_nmix_prpr`)처럼 알아보기 어려운 이름은 옆에 한글 뜻을 적습니다.

### 5. 명세서 규칙 (코드와 같이)

- 모듈마다 `docs/명세서/<모듈명>.md`를 둡니다. 양식: [docs/명세서/_양식.md](docs/명세서/_양식.md)
- 함수나 클래스의 입력·출력·예외가 바뀌면 **같은 PR에서 명세서도 고칩니다.** 명세서가 안 바뀐 PR은 리뷰에서 반려합니다.
- 상대방 모듈을 쓸 때는 코드를 뒤지기 전에 명세서를 먼저 봅니다. 명세서와 코드가 다르면 바로 알립니다.

### 6. 작업 보고 규칙 (서로에게 md로 보고)

- 작업이 끝날 때마다(최소 하루 1번) `docs/작업보고/YYYY-MM-DD_이름.md`를 작성해 PR에 같이 올립니다. 양식: [docs/작업보고/_양식.md](docs/작업보고/_양식.md)
- **Claude 등 AI가 쓴 초안을 그대로 붙여넣지 않습니다.** 초안은 참고만 하고, 반드시 본인이 읽고 가공해서 직접 씁니다.
  - 실제로 한 일과 다른 내용, 하지 않은 테스트, 과장된 표현은 지웁니다.
  - 상대가 읽고 바로 이어서 작업할 수 있게, 막힌 점과 상대에게 필요한 것을 구체적으로 씁니다.
- 상대 보고서는 다음 작업 시작 전에 읽고, 질문은 PR 댓글로 남깁니다.

### 7. 비밀값 규칙

- 앱키, 앱시크릿, 계좌번호, 텔레그램 토큰은 **절대 커밋하지 않습니다.**
- 로컬에서는 `.env`(git 제외) 또는 Windows 자격 증명(keyring)에 저장합니다.
- 커밋 전 확인: `git diff --cached`로 비밀값이 섞이지 않았는지 봅니다.
- 실수로 올렸다면 즉시 상대에게 알리고, 해당 키를 KIS Developers에서 **재발급**합니다 (커밋 삭제만으로는 부족).

## 폴더 구조 (예정)

```
주식자동매매/
├─ src/autotrader/
│  ├─ api/          # [A] KIS 인증, REST/WebSocket 클라이언트, 호출 제한
│  ├─ market/       # [A] 국내·해외 시세 수집, 환율
│  ├─ strategy/     # [A] 지표 계산, 합의 신호 엔진
│  ├─ order/        # [A] 주문 실행, 중복 주문 방지, 체결 추적
│  ├─ risk/         # [A] 위험 한도 가드
│  ├─ recovery/     # [A] 재접속, 재시작 동기화
│  ├─ scheduler/    # [B] 장 시간 스케줄 (국내/미국, 서머타임)
│  ├─ storage/      # [B] SQLite 모델, 저장소
│  ├─ notify/       # [B] 텔레그램 알림
│  ├─ config/       # [B] 설정 로딩, keyring
│  └─ ui/           # [B] PySide6 GUI
├─ tests/           # 모듈별 테스트 (작성자가 자기 모듈 테스트 담당)
├─ 설계_정리.md
├─ docs/
│  ├─ 개발환경.md
│  ├─ 역할분담.md
│  ├─ 명세서/
│  └─ 작업보고/
└─ .github/pull_request_template.md
```
