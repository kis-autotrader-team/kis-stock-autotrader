# 역할 분담 (2명)

- **A = 엔진 담당:** 돈이 움직이는 쪽. 시세 → 신호 → 위험 한도 → 주문 → 복구
- **B = 제품 담당:** 사람이 보고 만지는 쪽 + 운영 기반. 화면, 설정, 저장, 알림, 스케줄, 배포, 테스트 자동화

원칙
1. 폴더 단위로 담당을 나눕니다. 상대 폴더를 고쳐야 하면 직접 고치지 말고 상대에게 요청하거나, PR에서 상대 승인을 받습니다.
2. 두 사람이 만나는 지점(인터페이스)은 **명세서로 먼저 합의**하고 코드를 씁니다. 3장 참고.
3. 각자 자기 모듈의 테스트와 명세서를 책임집니다.
4. 리뷰는 서로 합니다. A의 PR은 B가, B의 PR은 A가 승인합니다.

---

## 1. A (엔진 담당) 상세

| 모듈 | 할 일 | 완료 기준 |
|---|---|---|
| `api/auth` | 접근 토큰 발급, 만료 전 자동 갱신, 모의/실전 도메인 전환 | 토큰 만료 상황을 테스트로 재현해 자동 갱신 확인 |
| `api/client` | REST 공통 호출(헤더, tr_id, 에러 코드 처리), 재시도 | 네트워크 오류·서버 오류 시 재시도, 실패 시 명확한 예외 |
| `api/ratelimit` | 초당 호출 수 제한 (실전/모의 수치 다름) | 연속 호출 테스트에서 제한 초과 에러 0건 |
| `api/websocket` | 실시간 시세·체결통보 연결, 끊기면 재접속 | 강제로 끊었을 때 자동 재접속 + 재구독 |
| `market` | 국내·해외 현재가, 일봉/분봉, 환율 조회 → 공통 `Quote`, `Candle` 모델로 변환 | 국내 1종목, 미국 1종목 조회가 같은 모델로 나옴 |
| `strategy/indicators` | RSI, 이동평균 교차, MACD (+ 여유 있으면 볼린저밴드) | 알려진 값과 비교하는 테스트 통과 |
| `strategy/engine` | 지표별 점수 → "N개 중 M개 동의" 판단 → `Signal` 생성 | 설정값 조합별 테스트 통과, 판단 근거가 `Signal`에 담김 |
| `risk` | 일일 손실 한도, 종목당 비중, 종목 손절, 1회 주문 한도 | **모든 한도의 경계값 테스트 통과.** 가드 없이 주문하는 경로가 없음 |
| `order` | 주문 실행, 미체결·체결 추적, 중복 주문 방지(주문 키) | 같은 신호 두 번 들어와도 주문 1건 |
| `recovery` | 재시작 시 잔고·미체결 재동기화, 장애 후 운영 재개 | PC 재시작 시나리오 테스트 통과 |

A가 B에게 넘겨줄 것: `Quote`, `Candle`, `Signal`, `OrderResult`, `RiskDecision` 모델과 이벤트(체결, 손절, 한도 도달, 장애)

## 2. B (제품 담당) 상세

| 모듈 | 할 일 | 완료 기준 |
|---|---|---|
| 프로젝트 기반 | 폴더 구조, `pyproject.toml`, uv 설정, ruff 설정, PR 템플릿, GitHub Actions(테스트·린트 자동 실행) | PR 올리면 테스트·린트 자동 실행 |
| `config` | `.env` 로딩, 설정 검증, keyring 저장·조회, 모의/실전 모드 값 | 잘못된 설정이면 실행 전에 명확한 에러 |
| `storage` | SQLite 스키마(주문, 체결, 신호·근거, 일일 손익, 설정 이력), 저장소 함수 | 프로그램 재시작 후에도 기록 유지 |
| `scheduler` | 국내장(09:00~15:30 KST), 미국장(뉴욕 09:30~16:00, 서머타임 자동) 시작·종료, 휴장일 처리 | 서머타임 전후 날짜로 테스트 통과 |
| `notify` | 텔레그램 전송: 체결, 손절, 한도 정지, 장애, 재접속 | 전송 실패해도 프로그램이 죽지 않음 |
| `ui/dashboard` | 국내·미국 잔고, 평가손익, 원화 환산 비중 (MVP 1) | 국내+미국 합계가 증권사 앱과 일치 |
| `ui/settings` | 지표 켜기/끄기, 임계값, 합의 조건, 위험 한도, 대상 종목 | 잘못된 값(예: 손실 한도 +5%) 입력 차단 |
| `ui/logs` | 매매 근거 로그 화면, 필터(날짜, 종목, 국내/미국) | "왜 샀는지"가 한 줄로 보임 |
| `ui/mode` | 모의 → 실전 전환 확인 절차 (경고 + 재확인 입력) | 실수로 한 번 클릭해서 실전 전환 불가 |
| 배포 | PyInstaller로 exe, 첫 실행 설정 마법사 | 새 PC에서 30분 안에 첫 실행 |
| 문서 | 사용자 매뉴얼, 설치 가이드 | 상대방이 매뉴얼만 보고 설치 성공 |

B가 A에게 넘겨줄 것: 설정 객체(`Settings`), 저장소 함수, 알림 함수, 스케줄 이벤트(장 시작/종료)

## 3. 두 사람이 먼저 합의할 인터페이스 (1~2일차)

코드를 쓰기 전에 아래를 `docs/명세서/인터페이스.md`에 정하고 둘 다 승인합니다.

| 인터페이스 | 만드는 사람 | 쓰는 사람 | 합의할 내용 |
|---|---|---|---|
| `Settings` | B | A | 지표 설정, 위험 한도, 모의/실전, 대상 종목의 필드 이름과 타입 |
| `Quote`, `Candle` | A | B | 국내·해외 공통 필드, 통화, 시간대 |
| `Signal` | A | B | 종목, 매수/매도, 지표별 점수, 판단 근거 문자열 |
| `RiskDecision` | A | B | 허용/차단, 차단 이유 |
| `OrderResult` | A | B | 주문번호, 상태, 체결가·수량 |
| 이벤트 | A | B | 체결/손절/한도 정지/장애/재접속 이벤트 구조 |
| 저장소 함수 | B | A | `save_signal`, `save_order` 등 함수 이름과 인자 |
| 알림 함수 | B | A | `notify(event)` 형태 |

합의 전까지는 서로 가짜 객체(mock)로 개발합니다.

## 5. 매일 하는 일

1. 시작 전: `git pull`, 상대의 최신 작업보고 읽기
2. 작업: 작은 단위로 커밋
3. 종료 전: PR 올리기 + 작업보고 작성 + 상대 PR 리뷰
4. 막히면 30분 이상 혼자 붙잡지 말고 바로 공유
